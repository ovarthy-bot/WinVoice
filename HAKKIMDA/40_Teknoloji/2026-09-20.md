# NODEx — Kişisel Bilgi Yönetimi Uygulaması

#teknoloji #flutter #proje-speki

## Rol

Kıdemli bir Flutter/Dart yazılım mimarı, mobil/desktop UI/UX mühendisi ve bilgi yönetimi uygulamaları konusunda uzman bir yazılım geliştiricisin.

Flutter kullanarak **Windows + Android** platformlarında çalışan, modern, profesyonel, yüksek performanslı ve ölçeklenebilir bir kişisel bilgi yönetimi / not alma uygulaması geliştir. Uygulamanın çalışma mantığı Obsidian benzeri Markdown tabanlı olacak ancak uygulama Obsidian'ın birebir kopyası olmayacak.

**Uygulamanın en önemli farklılıkları:**

- Çok hızlı ve her zaman erişilebilir global arama
- Windows + Android çapraz platform desteği
- S Pen / stylus ile gelişmiş el yazısı ve çizim
- Klavye + el yazısını aynı not içerisinde birlikte kullanabilme
- WikiLink bağlantıları
- Backlink sistemi
- Graph View
- OCR ile el yazısını metne dönüştürme
- Markdown dosyalarını uygulamaya kilitlememe
- Modern, profesyonel ve sinematik UI
- Çevrimdışı-first çalışma

## 1. Platform

Tek kod tabanı: Flutter, Dart, Windows, Android. iOS, macOS ve Web şu aşamada geliştirme kapsamı dışındadır. Ancak mimari ileride bu platformların eklenmesine engel olmayacak şekilde hazırlanmalıdır.

## 2. Temel Felsefe

Uygulamanın en önemli mimari prensibi:

> Uygulama notların sahibi değildir; notlara erişmek, düzenlemek, bağlamak, aramak ve görselleştirmek için kullanılan araçtır.

Markdown dosyaları kullanıcının gerçek verisidir. Örneğin:

```
MyWorkspace/
├── İş/
│   ├── Motor Kontrol.md
│   ├── NRC Kayıtları.md
│   └── Projeler/
│       └── Proje A.md
├── Sosyal/
│   ├── Kitaplar.md
│   └── Filmler.md
└── Attachments/
```

Uygulama silinse bile `.md` dosyaları normal dosyalar olarak kullanılmaya devam edebilmelidir. Kullanıcı bu dosyaları Obsidian, VS Code, Notepad veya başka Markdown editörleriyle açabilmelidir. Uygulamanın kendi veritabanı Markdown dosyalarının yerine geçmemelidir.

## 3. Mimari

Clean Architecture + Feature-based Architecture kullan.

```
lib/
├── core/ (constants, errors, extensions, helpers, services, theme, utils, platform)
├── features/
│   ├── workspace/ (data, domain, presentation)
│   ├── notes/ (data, domain, presentation)
│   ├── editor/ (data, domain, presentation)
│   ├── handwriting/ (data, domain, presentation)
│   ├── search/ (data, domain, presentation)
│   ├── wikilinks/
│   ├── backlinks/
│   ├── graph/
│   ├── ocr/
│   ├── attachments/
│   ├── settings/
│   └── trash/
├── app/ (app.dart, router.dart, dependency_injection.dart)
└── main.dart
```

State management için Riverpod veya benzeri modern ve ölçeklenebilir bir çözüm kullan. Dependency Injection uygulanmalıdır. Business logic UI widgetlarının içine yazılmamalıdır.

## 4. Veri Mimarisi

İki farklı veri katmanı oluştur.

**A. Gerçek kullanıcı verisi:** Markdown dosyaları (`*.md`) — bunlar source of truth olacaktır.

**B. Uygulama index/cache verisi:** SQLite kullanılabilir. Örnek tablolar: notes, folders, links, backlinks, tags, search_index, handwriting_metadata, attachments. SQLite; arama hızlandırma, graph oluşturma, backlink hesaplama, metadata, son açılan notlar, indeksleme amacıyla kullanılmalıdır.

Markdown dosyası ile SQLite arasında veri çakışması olduğunda Markdown dosyası esas alınmalıdır.

## 5. Workspace

Kullanıcı ilk çalıştırmada bir Workspace seçmelidir. Windows'ta "Select Workspace Folder"; Android'de uygun klasör erişim mekanizması kullanılmalı.

Workspace seçildikten sonra workspace (klasörler, markdown dosyaları, ekler) taransın. Uygulama açıldığında workspace otomatik olarak yeniden indekslenmelidir. Dosya değişikliklerini algılamak için mümkün olduğunca filesystem watcher kullanılmalıdır.

## 6. Markdown

Markdown desteği sağlam olmalıdır. Desteklenmesi gereken temel özellikler: başlıklar, kalın, italik, listeler, numaralı listeler, checkbox, code block, inline code, tablolar, blockquote, linkler, görseller, WikiLink, etiketler.

Örnek:

```markdown
# Motor Kontrolü

## Kontrol Sonucu

Motor 2 kontrol edildi.

- [x] Yağ seviyesi
- [x] Hidrolik
- [ ] Final kontrol

[[NRC Kayıtları]]

#motor
#bakım
```

## 7. Editor

Editor iki farklı içerik tipini desteklemelidir:

- **Text Layer:** Markdown metni.
- **Ink Layer:** S Pen / stylus çizimleri.

Bunlar aynı not içerisinde birlikte bulunabilir (Markdown content, handwriting layer 1, handwriting layer 2, attachments). El yazısını Markdown dosyasının içerisine zorla bitmap olarak gömme; el yazısı ayrı metadata/drawing dosyalarında saklanmalıdır.

## 8. S Pen / Stylus

Android'de S Pen desteği birinci sınıf özellik olmalıdır. Desteklenecek araçlar: Pen, Pencil, Highlighter, Eraser, Lasso/selection, Undo, Redo, Stroke thickness, Opacity, farklı renkler. Kalem basıncı mümkün olduğunda kullanılmalıdır.

S Pen ile çizim yapılırken parmak ile yanlışlıkla çizim yapılmamalı, avuç içi reddedilmeli, stylus input ile touch input ayrıştırılmalı. İki parmak pan/zoom için kullanılabilmelidir.

## 9. El Yazısı Veri Modeli

El yazısını yalnızca PNG/JPG olarak kaydetme; stroke tabanlı veri modeli kullan. Örnek:

```json
{
  "pageId": "page_001",
  "strokes": [
    {
      "points": [{ "x": 120.2, "y": 250.5, "pressure": 0.7, "timestamp": 123456 }],
      "color": "#000000",
      "width": 3.0
    }
  ]
}
```

Bu sayede zoom, resize, undo, redo, stroke silme, selection, OCR işlemleri mümkün olur.

## 10. Note Sayfa Modeli

Bir not gerektiğinde birden fazla sayfaya sahip olabilir (örn. `Motor Kontrolü.md` → Page 1, 2, 3). Her sayfa Markdown + Ink + Images + Attachments içerebilir. Kullanıcı yeni sayfa ekleyebilmeli, sayfa silebilmeli, sayfaları sıralayabilmeli.

## 11. OCR

El yazısı için OCR sistemi ekle. Akış: S Pen handwriting → OCR → recognized text → search index. OCR sonucunda kullanıcı isterse el yazısını gerçek Markdown metnine dönüştürebilmelidir. Ancak OCR orijinal el yazısını silmemelidir — original handwriting + recognized text birlikte korunmalıdır. OCR hatalı olabileceği için kullanıcı sonucu düzenleyebilmelidir.

## 12. Global Search

Bu uygulamanın en önemli özelliklerinden biri global aramadır. Arama kutusu Windows ve Android'de her zaman kolay erişilebilir olmalıdır.

- Windows: `Ctrl + K` veya uygun başka global shortcut.
- Android: üstte sabit arama, bottom navigation üzerinde Search, mümkünse floating search erişimi.

Kullanıcı hiçbir zaman arama ekranını bulmak için menüler arasında dolaşmamalıdır.

## 13. Search Engine

Arama sadece dosya adında çalışmamalıdır. Arama; dosya adı, Markdown içeriği, WikiLinks, tags, backlinks, OCR metni, el yazısı OCR sonucu, klasör, attachment metadata üzerinde çalışabilmelidir.

Örnek: "motor" araması → Motor Kontrolü, NRC Kayıtları, Motor Bakım Planı sonuçlarını vermeli.

Arama sonuçlarında eşleşen bölüm highlight edilmelidir. Arama mümkün olduğunca anlık çalışmalıdır. Büyük workspace'lerde UI donmamalıdır.

## 14. Search Index

SQLite FTS5 veya eşdeğer güçlü local full-text search çözümü kullan. Akış: query → FTS index → ranked results → UI. Workspace ilk açıldığında indeks oluşturulmalıdır. Daha sonra yalnızca değişen dosyalar yeniden indekslenmelidir.

## 15. WikiLink

Obsidian benzeri `[[Motor Kontrolü]]` syntax desteklenmelidir. Kullanıcı `[[Mot...` yazdığında autocomplete açılmalıdır. Not seçildiğinde `[[Motor Kontrolü]]` oluşturulmalıdır. Ctrl+Click / uygun Android gesture ile bağlantılı nota gidilebilmelidir.

## 16. Backlink

Her not için Backlinks alanı bulunmalıdır (örn. Motor Kontrolü ← NRC Kayıtları ← Bakım Planı ← Teknik Notlar). Bir not silindiğinde backlink sistemi bozulmamalıdır.

## 17. Graph View

Workspace içerisindeki notları grafik olarak göster. Graph zoom, pan, node selection, node search, bağlantı çizgileri, filtreleme desteklemelidir. Node seçildiğinde ilgili nota gidilebilmelidir. Graph hesaplaması UI thread'i bloke etmemelidir.

## 18. Home Screen

Ana ekran sade ama güçlü olmalıdır: üstte arama, Workspace klasörleri (örn. Sosyal, İş), Recent Notes listesi, yeni not butonu. İlk aşamada örnek klasörler olabilir ancak bunlar uygulamanın sabit klasörleri olmamalıdır — kullanıcı istediği kadar klasör oluşturabilmelidir.

## 19. Yeni Not

Yeni not butonuna basıldığında her zaman yeni ve boş bir not oluştur. Daha önce açılmış not kesinlikle tekrar açılmamalıdır. Yeni not `Untitled.md` olarak başlayabilir; kullanıcı ilk başlık verdiğinde uygun dosya adı oluşturulabilir. Boş not kaydedilmemelidir (yeni not açıldı → kullanıcı hiçbir şey yazmadı → uygulama kapandı → dosya oluşturma).

## 20. Dosya / Klasör Yönetimi

Desteklenmeli: yeni klasör, yeni not, yeniden adlandır, taşı, sil, geri yükle, çöp kutusu, workspace değiştir. Dosya işlemlerinde kullanıcı verisini kaybetmeye karşı koruma uygulanmalıdır.

## 21. Trash

Silinen notlar doğrudan fiziksel olarak yok edilmemelidir; önce Trash alanına gönderilmelidir. Trash not adı, içerik önizlemesi, silinme tarihi göstermelidir. Kullanıcı Restore / Delete Permanently işlemlerini yapabilmelidir.

## 22. Attachments

Markdown notlarına PNG, JPG, JPEG, PDF ve diğer uygun dosyalar eklenebilmelidir. Workspace içerisinde `Attachments/` klasörü kullanılabilir. Markdown içindeki linkler mümkün olduğunca standart dosya bağlantıları şeklinde tutulmalıdır. Uygulama kendi özel ve okunamaz dosya formatına bağımlı olmamalıdır.

## 23. PDF

PDF temel olarak görüntülenebilmelidir. İleride PDF üzerine çizim, S Pen annotation, highlight, bookmark eklenebilecek şekilde mimari hazırlanmalıdır. PDF dosyasının orijinali değiştirilmemelidir; annotation katmanı ayrı tutulmalıdır.

## 24. Android S Pen Özel Davranışları

Android tarafında mümkün olduğunda Samsung S Pen özelliklerini destekle. Ancak uygulamanın temel fonksiyonları Samsung'a bağımlı olmamalıdır. S Pen çıkarılması algılanabiliyorsa kullanıcı ayarından davranış seçilebilir (çizim modunu aç / yeni not oluştur / son notu aç / hiçbir şey yapma). S Pen yuvaya takıldığında varsayılan olarak agresif sistem davranışı gerçekleştirme; ekranı kapatma gibi davranışlar ancak kullanıcı açıkça etkinleştirirse uygulanmalıdır.

## 25. Touch / Mouse / Stylus Gesture Sistemi

Input sistemi dikkatli tasarlanmalıdır.

- **Mouse:** click, double click, right click, drag
- **Touch:** tap, double tap, long press, pinch zoom, pan
- **Stylus:** draw, erase, select

Input eventleri birbirini bozmamalıdır — özellikle S Pen çizim + iki parmak zoom + normal scroll gesture conflict oluşturmamalıdır.

## 26. Responsive UI

Windows ve Android için aynı UI'ı küçültüp büyütme; platforma uygun adaptive layout oluştur.

- **Windows:** Sidebar (Search, Home, Workspace, Graph, Backlinks, Settings) + Main Content
- **Android:** Top Search, Content, Bottom Navigation

Android'de geniş ekran/tablet varsa iki kolonlu adaptive layout kullanılabilir.

## 27. Tema

Modern ve profesyonel tasarım kullan; çocuksu UI istenmiyor. Tasarım sade, premium, sinematik, modern, yüksek okunabilirlik, düşük görsel karmaşa olmalıdır. Dark mode OLED-friendly olabilecek şekilde tasarlanmalıdır. Light mode da bulunmalıdır. Kullanıcı System/Light/Dark seçebilsin.

## 28. Animasyon

Animasyonlar kullanılabilir ancak uygulamayı yavaşlatmamalıdır (note transition, search results, graph, sidebar, modal, page switching için kısa ve profesyonel animasyonlar). Aşırı animasyon kullanılmamalıdır.

## 29. Offline-First

Uygulamanın temel özellikleri internetsiz çalışmalıdır — internet gerekli değildir. Markdown okuma, yazma, arama, graph, backlink, handwriting lokal olarak çalışmalıdır.

## 30. Performans

Özellikle büyük workspace düşünülmelidir (10.000+ Markdown dosyası, 100.000+ backlink, çok sayıda handwriting stroke). Kurallar: ağır işlemleri isolate/background işleminde çalıştır, dosya taramasını UI thread'de yapma, Graph hesaplamasını UI thread'de yapma, OCR işlemini UI thread'de yapma, search index güncellemelerini optimize et, lazy loading kullan, liste virtualization kullan, gereksiz rebuildlerden kaçın.

## 31. Autosave

Markdown düzenleyicide otomatik kayıt sistemi olmalıdır. Ancak her karakterde fiziksel disk yazımı yapılmamalıdır — debounce kullan (user typing → 500–1000 ms inactivity → save → update index). Dosya kaydedilirken veri kaybına karşı güvenli atomic write kullanılmalıdır.

## 32. Dosya Çakışması

Aynı Markdown dosyası uygulama dışında değiştirilirse uygulama bunu algılamalıdır (app açık → VS Code aynı .md dosyasını değiştirdi → file watcher → değişiklik algılandı → index update → kullanıcıya uygun şekilde güncel içerik göster). Kullanıcının değişiklikleri sessizce ezilmemelidir.

## 33. Import / Export

Kullanıcı workspace klasörü seçtiğinde mevcut Markdown dosyaları otomatik olarak algılanmalıdır. Ekstra proprietary import formatı oluşturma. Export gerektiğinde Markdown files + attachments + optional handwriting export sunulabilir.

## 34. Settings

- **General:** Workspace, Language, Theme, Autosave
- **Editor:** Font, Font size, Line spacing, Markdown preview, Tab size
- **Handwriting:** Default pen, Thickness, Color, Pressure sensitivity, Palm rejection, S Pen behavior
- **Search:** Search OCR text, Search filenames, Search tags, Search attachments
- **Graph:** Node size, Link visibility, Animation, Filters

## 35. Keyboard Shortcuts — Windows

En az: `Ctrl+K` Global Search, `Ctrl+N` New Note, `Ctrl+S` Save, `Ctrl+Shift+N` New Folder, `Ctrl+P` Command Palette, `Ctrl+F` Current Note Search, `Ctrl+Z` Undo, `Ctrl+Shift+Z` Redo, `Ctrl+W` Close Note. Shortcutlar daha sonra kullanıcı tarafından özelleştirilebilir olmalıdır.

## 36. Command Palette

Windows'ta `Ctrl+P` ile command palette açılabilir: New Note, New Folder, Search Notes, Open Graph, Open Settings, Toggle Dark Mode, Reindex Workspace, Open Recent Note.

## 37. Recent Notes

Son açılan notlar tutulmalıdır; ana ekranda Recent alanı gösterilebilir. Recent metadata uygulamanın SQLite indexinde tutulabilir; Markdown dosyasının içerisine yazılmamalıdır.

## 38. Favorites

Notlar favorilere eklenebilmeli. Favori bilgisi Markdown içine metadata olarak zorla yazılmamalı; SQLite metadata kullanılabilir.

## 39. Tag Sistemi

Markdown içindeki `#uçak #motor #bakım` gibi tagleri algıla. Tag'e tıklanınca ilgili notlar listelenmelidir. Search ile birlikte çalışmalıdır.

## 40. Not Önizlemesi

Arama sonuçlarında ve not listesinde başlık, klasör, son değiştirilme, ilk birkaç satır, tagler gösterilebilir. El yazısı varsa küçük thumbnail oluşturulabilir.

## 41. Data Safety

Kullanıcı verisi en önemli önceliktir. Şunları yapma: Markdown dosyalarını gizli proprietary database formatına dönüştürme, dosyaları sadece uygulamanın okuyabileceği hale getirme, kullanıcıya ait `.md` dosyasını sessizce silme, external file changes üzerine otomatik yazıp ezme. Her kritik işlem için güvenli yaklaşım kullan.

## 42. Error Handling

Uygulama çökmek yerine anlamlı hata göstermelidir (örn. "Workspace okunamadı. Dosya erişimi reddedildi. [Tekrar dene] [Workspace değiştir]"). Developer mode için ayrıntılı log sistemi oluştur. Production'da hassas kullanıcı içeriğini loglama.

## 43. Test

Test altyapısı oluştur.

- **Unit tests:** Markdown parser, WikiLink parser, backlink generator, search indexing, file synchronization, handwriting serialization, graph generation
- **Widget tests:** Search, Note editor, Note list, Graph, handwriting toolbar
- **Integration tests:** create note, edit note, save, reopen, search, rename, move, delete, restore, external file modification

## 44. Uygulama Başlangıç Akışı

İlk açılış: "NODEx — Your notes. Your files. Your knowledge. [Select Workspace] [Create Workspace]". Workspace seçildikten sonra scanning workspace / indexing notes / building graph işlemleri yapılmalı, ilerleme gösterilmeli.

## 45. Note Açılış Akışı

User selects note → Load Markdown → Load handwriting metadata → Load attachments → Render editor. Dosya yoksa "Note unavailable" göster.

## 46. Search Akışı

User types query → Debounce → SQLite FTS → Metadata filters → OCR results → Rank results → Display. Sonuçlar mümkün olduğunca gecikmesiz görünmelidir.

## 47. Graph Akışı

Workspace → Parse WikiLinks → Build nodes → Build edges → Graph engine → Render. Graph görünümü açıldığında bütün workspace yeniden parse edilmemeli; index üzerinden çalışmalıdır.

## 48. Handwriting Akışı

Stylus event → Input processor → Stroke builder → Canvas renderer → Autosave → Optional OCR → Search index. Stroke'lar vector olarak saklanmalıdır.

## 49. OCR Akışı

Selected handwriting → Rasterize/prepare → OCR engine → Recognized text → User review → Save OCR text → Update search index. OCR sonucu kullanıcı tarafından onaylanmadan orijinal el yazısının yerine geçmemelidir.

## 50. UI Componentleri

Reusable componentler oluştur: AppSidebar, GlobalSearchBar, SearchResultTile, NoteListTile, MarkdownEditor, MarkdownPreview, WikiLinkAutocomplete, BacklinkPanel, GraphView, HandwritingCanvas, PenToolbar, PageNavigator, AttachmentViewer, TrashView, SettingsView, CommandPalette.

## 51. Kod Kalitesi

Kod null-safe, strongly typed, modüler, test edilebilir, maintainable olmalıdır. Widgetlarda yüzlerce satırlık business logic oluşturma. Tek bir `main.dart` dosyasında bütün uygulamayı yazma. Magic number kullanımını azalt; constants kullan.

## 52. Package Seçimi

Bir package kullanmadan önce kontrol et: Flutter Windows desteği var mı? Android desteği var mı? Aktif olarak geliştiriliyor mu? Lisansı uygun mu? Kritik bir özelliği package'a tamamen bağımlı hale getiriyor mu? Bir package platformlardan birini desteklemiyorsa abstraction/interface oluştur (örn. `abstract class OcrService { Future<String> recognize(...); }`).

## 53. Platform Abstraction

Özellikle File system, Folder picker, Stylus, S Pen, OCR, Window management, Keyboard shortcuts platform abstraction üzerinden tasarlanmalıdır (örn. `WorkspaceService`, `WindowsWorkspaceService`, `AndroidWorkspaceService`).

## 54. Android Dosya Erişimi

Android'de doğrudan filesystem varsayımı yapma; modern Android storage modeline uygun çalış. Kullanıcı workspace seçtiğinde gerekli erişim izinlerini güvenli şekilde yönet. Uygulama yeniden açıldığında workspace erişimi devam ettirilebiliyorsa persistent permission kullan.

## 55. Windows Dosya Erişimi

Windows'ta kullanıcı seçtiği normal klasör üzerinde çalış (örn. `C:\Users\User\Documents\NODEx`). Dosyalar Explorer üzerinden görülebilmelidir.

## 56. Uygulama Adı

Geçici uygulama adı: **NODEx**. İsim daha sonra değiştirilebilir. Marka adını kodun her yerine hard-code etme.

## 57. Geliştirme Aşamaları

- **Faz 7:** Performance, large workspace optimization, crash/error handling, tests, backup/export, polish.

## 60. Önemli: Kod Yazmadan Önce

Projeyi oluştururken önce bütün mimariyi düşün. İlk cevapta hemen yüzlerce dosya üretme. Önce Architecture, Folder structure, Dependencies, Data model, State management, Navigation, Storage strategy, Platform strategy planını oluştur; sonra Faz 1'i uygula.

## 61. İlk Sürüm Başarı Kriterleri

Faz 1 tamamlandığında şu senaryo çalışmalıdır — Windows: Workspace seç → Yeni klasör oluştur → Yeni not oluştur → Markdown yaz → Kaydet → Uygulamayı kapat → Tekrar aç → Workspace otomatik yüklenir → Not bulunur → Not açılır → Markdown içerik kaybolmamıştır. Android: Workspace → Yeni not → Klavyeyle yaz → Kaydet → Tekrar aç → İçerik mevcut.

## 62. S Pen Başarı Kriteri

Android cihazda: Not aç → S Pen ile çiz → Stroke oluşur → Parmağı kullanarak sayfayı kaydır → İki parmakla zoom → S Pen ile tekrar çiz → Undo → Redo → Notu kapat → Tekrar aç → El yazısı kaybolmamış.

## 63. Hibrit Not Başarı Kriteri

Aynı notta Markdown text + S Pen handwriting + image + WikiLink bulunabilmelidir. Örnek:

```markdown
# Motor Kontrolü

Motor 2 kontrol edildi.

[ S PEN EL YAZISI ]

Kontrol sonucu:
[[NRC Kayıtları]]

#motor
```

## 64. Search Başarı Kriteri

Kullanıcı "Motor" araması yaptığında Markdown içindeki, dosya adındaki, taglerdeki, WikiLinklerdeki, OCR sonucundaki "Motor" bulunabilmelidir.

## 65. Son Hedef

Ortaya çıkacak uygulama Markdown, Handwriting ve Knowledge'ı Search/Links/Graph üzerinden tek yerde birleştirmelidir. Bu uygulama:

> "Markdown tabanlı, hızlı arama odaklı, el yazısı destekli kişisel bilgi işletim sistemi"

gibi davranmalıdır. Basit bir not uygulaması, basit bir Markdown editörü veya sadece bir Obsidian klonu oluşturma. Klavye ile yazan kullanıcı ile S Pen kullanan kullanıcıyı aynı bilgi sistemi içerisinde buluşturan, Windows ve Android üzerinde çalışan, dosyalarını kullanıcıya ait bırakan modern bir kişisel bilgi yönetim platformu oluştur.
